## Sources and standards

- [AGE v1 encrypted stream specification](https://c2sp.org/age); structural header is only an early confidentiality check, not authentication/decryption.
- [Azure Key Vault Get Secret REST API](https://learn.microsoft.com/en-us/rest/api/keyvault/secrets/get-secret/get-secret), OAuth scope `https://vault.azure.net/.default`, secret's `id` and `attributes` fields.
- [PostgreSQL 17 libpq password-file escaping and mode](https://www.postgresql.org/docs/17/libpq-pgpass.html), [PostgreSQL 17 TLS connection options](https://www.postgresql.org/docs/17/libpq-ssl.html).
- [Azure Container Apps security, identity and job start permissions](https://learn.microsoft.com/en-us/azure/container-apps/security); [Azure manual Jobs](https://learn.microsoft.com/en-us/azure/container-apps/jobs).
- [Existing read-only Azure preflight](../../ops/cloud-backup/azure-readonly-preflight.sh); [quality-first Azure resource IAM/cost proposal](AZURE_BACKUP_REGISTRY_VAULT_JOB_PREPARATION.md).

4. **Review-only Container Apps Job configuration:** manual trigger, no schedule/event trigger, no ingress, one replica, zero retries, timeout 1800s, 0.5 vCPU / 1Gi memory, default `--preflight`, fixed scan-verified **signed manifest digest**, read-only root where supported, writable ephemeral `/dev/shm` tmpfs, no private AGE decryption identity in job, least-privilege registry/vault/blob RBAC, safe redacted logging with short retention and alarms. Do not run until target runtime and CLI support are proved.
5. **Non-data staging TLS test:** Separate authorization `AZURE_TLS_CHECK_APPROVED=YES`, stage-only valid CA root and managed identity Vault secret scope, `--check-tls` fixed SQL confirming own TLS session `pg_stat_ssl.ssl=true` with accepted TLS version, libpq `verify-full`. Evidence: time, selected staging alias, container image SHA, TLS protocol and sanitized PASS, not DB rows or passwords. A synthetic PASS is **not** accepted.
6. **Backup run (separate owner approval):** intentionally set `AZURE_EXPORT_APPROVED=YES` for a manual `--execute` only after release review; enforce AGE v1 guard before uploading, private Azure Blob if-none-match, AGE public recipient only and remote ciphertext SHA-256 readback. Retain current staging source metadata and minimum two protected recovery points.
7. **Independent disaster recovery proof:** A separately scoped recovery operator downloads the ciphertext into a **separate encrypted PG17/PostGIS target**, checks exact SHA-256, decrypts with the separately held AGE private key and validates PGDMP/custom archive and `pg_restore --exit-on-error`, then signs off schema, table counts, content digests, grants, roles, RLS, migration ledger, synthetic authentication and Render rollback. Never publish decrypted student content or actual secret endpoints in Git/Notion/chat.
8. **Only then:** independently approve staging OTP provider test and Render rollback rehearsal; production deployment and database migration remain separate decisions.
